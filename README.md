# G.I KO KO Voice Assistant

Native Android voice assistant for Redmi 9A / Android 10 with an ARMv7 (armeabi-v7a) release target.

## v0.3.0 features
- OpenAI-compatible online LLM chat (Groq and other compatible providers).
- On-device GGUF inference through llama.cpp native JNI, compiled for `armeabi-v7a`.
- Import GGUF into app-private storage and switch between ONLINE and OFFLINE modes.
- Low-memory defaults for older 32-bit phones: CPU-only inference, 2 threads, 512-token context, and up to 160 generated tokens.
- Provider connection test using the provider's `/models` endpoint.
- API key encrypted at rest with Android Keystore AES-GCM.
- Online AI function calling for calculator, app launch, and restricted Termux commands. Every tool action requires explicit user confirmation.
- Local conversation history (up to 200 messages) with clear-history control.
- Burmese speech recognition input with offline preference and English (US) Android Text-to-Speech output.
- Expanded, scrollable conversation area and floating assistant.
- ARMv7 debug and signed release APKs built by GitHub Actions.

## Offline model guidance
1. Download a **text-only GGUF instruct model**, preferably around **0.5B parameters in Q4 quantization** for the Redmi 9A's 32-bit ARMv7 and limited RAM.
2. In the app, tap **Import GGUF** and select the model file. The app copies it into private app storage and checks the GGUF header.
3. Tap **OFFLINE ON**. Messages are then generated by the local model without calling the configured online API.
4. Tap **ONLINE MODE** to return to the provider API.

The APK does not bundle a model. Import a compatible GGUF file yourself; keep at least the model size plus free working storage available. The importer currently accepts model files up to 700 MB. Large models, multimodal models, split GGUF sets, and models requiring more memory than the device has may fail to load. Local generation is CPU-only and can be slow on the Redmi 9A. The app loads the model for each response, so expect model-loading delay. CI packaging success does not replace a real-device inference test; confirm the model actually answers after installation.

Offline AI text generation does not require an internet connection after the GGUF is imported. Speech recognition and English TTS are provided by Android's installed speech/TTS services; offline voice operation depends on the corresponding offline language/voice packs being installed on the device. Android's offline speech preference is advisory and is not guaranteed by every recognition provider.


## Target device
- Redmi 9A / Android 10 (API 29)
- armeabi-v7a
- Kotlin + Jetpack Compose

## Configure online LLM
1. Open LLM Setup.
2. Enter an OpenAI-compatible Base URL, exact Model ID, and API key.
3. Tap TEST CONNECTION. The app checks the provider's /models endpoint.
4. Save, then send a message.

Example Groq Base URL: https://api.groq.com/openai/v1.
The model ID and API key must be obtained from the selected provider. No API key is bundled in the APK.

## Build and download
Open Actions → Android CI and Release → latest successful run → Artifacts.
- GI-KO-KO-Voice-Assistant-v0.3.0-offline-armv7 is the signed APK for direct installation.
- GI-KO-KO-Voice-Assistant-debug-armv7 is the debug APK.

The CI release APK uses the Android debug signing key so it can be installed directly for device testing. It is not Play Store upload signing. Use a private upload keystore before publishing through Google Play. Uninstalling a build signed with a different key may be required before installing this one.

## Safety
- App launching is restricted to a valid installed package name.
- Termux commands are restricted to pwd, ls, and python --version.
- AI-requested tools are never executed without the confirmation dialog.
- No root or Accessibility permission is required.
- Floating assistant requires Android's Display over other apps permission.
